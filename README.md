# Setup Guide

A VS Code extension that visualizes C program execution step-by-step, similar to PythonTutor.

---

## Prerequisites

Install these before anything else.

### 1. Node.js
Download and install from https://nodejs.org (LTS version).  
Verify: `node --version`

### 2. GDB + GCC (Windows — MSYS2)
Download MSYS2 from https://www.msys2.org and install it.  
Then open the MSYS2 UCRT64 terminal and run:
```bash
pacman -S mingw-w64-ucrt-x86_64-gcc mingw-w64-ucrt-x86_64-gdb
```
Add `C:\msys64\ucrt64\bin` to your Windows PATH:  
**Start → Search "Environment Variables" → Path → Edit → New → paste the path above**

Verify in PowerShell:
```powershell
gcc --version
gdb --version
```

### 3. VS Code
Download from https://code.visualstudio.com

---

## Project Structure

Your project folder should look exactly like this:

```
IseeC/
├── .vscode/
│   └── launch.json          ← tells VS Code how to run the extension (F5)
├── media/
│   └── tracer.py            ← GDB Python script that records execution
├── src/
│   ├── extension.ts         ← registers the command
│   └── VisualizerPanel.ts   ← all panel logic
├── out/                     ← auto-generated by tsc, do not edit
├── package.json
├── tsconfig.json
└── README.md
```

---

## File Setup

### Step 1 — `.vscode/launch.json`
Create the `.vscode` folder inside your project, then create `launch.json` with:

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Run Extension",
      "type": "extensionHost",
      "request": "launch",
      "args": [
        "--extensionDevelopmentPath=${workspaceFolder}"
      ],
      "outFiles": [
        "${workspaceFolder}/out/**/*.js"
      ],
      "preLaunchTask": "npm: compile"
    }
  ]
}
```

### Step 2 — `media/tracer.py`
Place the provided `tracer.py` file inside the `media/` folder.  
This is the GDB Python script that records every execution step into a JSON trace file.

### Step 3 — `src/VisualizerPanel.ts`
Replace the contents of `src/VisualizerPanel.ts` with the provided file.

---

## Install & Build

Open a terminal inside your project folder (`IseeC/`) and run:

```powershell
npm install
npm run compile
```

`npm install` downloads all dependencies into `node_modules/`.  
`npm run compile` converts TypeScript → JavaScript into the `out/` folder.

Re-run `npm run compile` every time you edit `.ts` files.

---

## Running the Extension

1. Open the `IseeC` folder in VS Code (`File → Open Folder`)
2. Press **F5**
3. A second VS Code window opens — this is the **Extension Development Host**
4. Inside that window, open a `.c` file
5. Press `Ctrl+Shift+V` (or right-click → **Visualize C Execution**)

---

## Writing C Programs for the Visualizer

> ⚠️ **Important:** Programs that use `scanf` or any other user input **will hang** because GDB runs in batch mode with no terminal. Use hardcoded values instead.

**❌ Won't work:**
```c
int n;
scanf("%d", &n);   // hangs forever waiting for input
```

**✅ Works:**
```c
int n = 5;
int arr[] = {4, 6, 3, 2, 1};   // hardcode your test data
```

### Example — Bubble Sort Demo
Save this as `bubbleSortDemo.c` and open it in the Extension Development Host:

```c
#include <stdio.h>

int main() {
    int n = 5;
    int arr[] = {4, 6, 3, 2, 1};

    for (int i = 0; i < n; i++) {
        for (int j = 0; j < n - 1; j++) {
            if (arr[j] > arr[j + 1]) {
                int temp = arr[j];
                arr[j] = arr[j + 1];
                arr[j + 1] = temp;
            }
        }
    }

    printf("Sorted: {");
    for (int i = 0; i < n; i++) {
        printf("%d", arr[i]);
        if (i < n - 1) printf(", ");
    }
    printf("}\n");

    return 0;
}
```

## Output Files

When you run the visualizer, two files are written to your Desktop:

| File | Description |
|------|-------------|
| `cvis_program.exe` | Compiled binary of your `.c` file |
| `cvis_trace.json` | Full execution trace used by the visualizer |

These are overwritten on every run. If you get a "Permission Denied" error, delete them manually from the Desktop and try again.

---

## Troubleshooting

### "Compilation failed: Permission Denied"
The previous `cvis_program.exe` is still locked by Windows.  
Fix: delete it from the Desktop before running again.
```powershell
Remove-Item C:\Users\<you>\Desktop\cvis_program.exe -Force
```

### "GDB did not produce trace.json"
Open the **C Visualizer** output panel (View → Output → select "C Visualizer") to see the full GDB log.  
Common causes:
- `tracer.py` not found in `media/` — check the `[tracer] checking:` lines in the output panel
- Program uses `scanf` — replace with hardcoded values
- GDB not on PATH — verify `gdb --version` works in PowerShell

### "Source file not pre-loaded"
Your `VisualizerPanel.ts` is an older version that doesn't send source code to the webview.  
Replace it with the latest provided version and recompile.

### Extension stuck on "Running GDB trace..."
GDB is hanging — most likely because the program is waiting for input (`scanf`).  
Use a hardcoded version of your program instead.

## VS Code Settings (optional)

Add these to your VS Code `settings.json` to customize the extension:

```json
{
  "cVisualizer.compiler": "gcc",
  "cVisualizer.compilerFlags": "-g -O0 -Wall",
  "cVisualizer.gdbPath": "gdb",
  "cVisualizer.maxSteps": 5000
}
```

## How It Works

```
Your .c file
     │
     ▼
gcc -g -O0          ← compiles with debug symbols
     │
     ▼
cvis_program.exe
     │
     ▼
gdb -batch          ← runs the binary under GDB
  + tracer.py       ← Python script hooks into GDB, steps through execution
     │
     ▼
cvis_trace.json     ← JSON array of every step: line, locals, stack, heap
     │
     ▼
VS Code Webview     ← reads the trace and renders the visualizer UI
```
